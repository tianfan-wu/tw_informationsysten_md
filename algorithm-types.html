Why algorithms matter

Different questions require different learning strategies.

A machine learning algorithm is a procedure for finding useful patterns in data. The right choice depends on the available labels, the desired prediction or pattern, and the structure of the data.

From a data analyst's perspective, selection begins with the business question, the available labels, the data structure, and the level of explanation stakeholders need. This framework compares common approaches without treating their categories as rigid boundaries.

01 · Learning map

Two ways to discover structure

The defining difference is whether the training data includes a target answer.

Supervised

Learn from labeled examples

The model studies inputs paired with known outcomes, then learns a mapping that can predict a label or value for new data.

Labeled data→Train model→Predict
Unsupervised

Find patterns without labels

The model receives inputs without target answers and searches for meaningful groups, compressed representations, or hidden structure.

Raw data→Find structure→Discover

02 · Algorithm atlas

Ten foundational approaches

Each card identifies the learning type, common application domains, operation, and a real-world example.

01Supervised

Linear Regression

Fits a straight-line relationship between input features and a continuous outcome by minimizing the difference between predicted and actual values.

Application domains

Tabular Data

Example use

Estimating a home's sale price from square footage, location, age, and number of rooms.
02Supervised

Gradient Boosting

Builds a sequence of small decision trees. Each new tree focuses on the errors left by the earlier trees, and their combined predictions form a strong model.

Application domains

Tabular Data

Example use

Predicting customer churn from account activity, service history, demographics, and prior support interactions.
03Supervised

Decision Tree

Splits data through a sequence of if–then questions. Each branch narrows the possibilities until a leaf produces a class or numeric prediction.

Application domains

Tabular Data

Example use

Supporting loan decisions using income, debt, credit history, and employment data.
04Supervised

Random Forest

Trains many decision trees on varied samples and feature subsets, then combines their outputs to improve accuracy and reduce overfitting.

Application domains

Tabular DataComputer Vision

Example use

Flagging potentially fraudulent card transactions from behavioral and transaction features.
05Supervised

Support Vector Machine

Finds the boundary that separates classes with the widest possible margin; kernel functions can create curved boundaries for complex data.

Application domains

Tabular DataComputer VisionNLP

Example use

Classifying email as spam or legitimate from word-frequency features.
06Supervised

Transformer Models (BERT/GPT)

Uses attention to weigh relationships among words or tokens across an entire sequence. BERT emphasizes language understanding, while GPT predicts the next token to generate language.

Application domains

NLPGenerative AI

Example use

Summarizing thousands of customer comments, classifying sentiment, and drafting an analyst's first-pass findings.
07Supervised

Convolutional Neural Network

Learns small visual filters that detect local patterns such as edges and textures, then combines them into increasingly complex image features.

Application domains

Computer VisionGenerative AI

Example use

Detecting manufacturing defects in labeled product images before items leave the production line.
08Unsupervised

K-Means Clustering

Assigns observations to the nearest of K cluster centers, then repeatedly updates those centers until the groups stabilize.

Application domains

Tabular DataComputer Vision

Example use

Grouping retail customers into behavioral segments for tailored marketing strategies.
09Unsupervised

Principal Component Analysis

Rotates high-dimensional data onto new axes that preserve as much variation as possible, allowing fewer dimensions to represent most of the information.

Application domains

Tabular DataComputer VisionNLP

Example use

Reducing hundreds of sensor variables before visualizing or modeling equipment behavior.
10Unsupervised

GANs & Diffusion Models

A GAN trains a generator against a discriminator, while a diffusion model learns to reverse a gradual noising process. Both learn a data distribution and create new samples.

Application domains

Computer VisionGenerative AI

Example use

Creating product-concept images and privacy-conscious synthetic images for design exploration or model testing.

Classification note: These labels follow the assignment's supervised/unsupervised framework. Transformer pretraining is commonly self-supervised, and generative models can also be adapted through supervised fine-tuning or human feedback.

03 · Personal synthesis

Reflection

This reflection connects the technical framework to my work as a data analyst and to the professional value of a portfolio artifact.

01

What I learned

Creating this framework clarified that an algorithm should be classified along more than one dimension. Learning style explains whether the model learns from labeled outcomes or discovers structure without labels, while the application domain describes the form of the data and the problem being solved. A decision tree and a convolutional neural network can both be supervised, yet one is usually strongest with structured tables and the other with images. I also learned that generative AI extends beyond chatbots: transformers, GANs, and diffusion models learn patterns that can produce new text or images.

02

How I would select a model

As a data analyst, I would begin with the decision the organization needs to make, then determine whether a reliable target variable exists. For labeled tabular data, I would compare an interpretable baseline such as linear regression or a decision tree with stronger ensemble methods such as random forests and gradient boosting. For unlabeled exploration, I would consider K-means or PCA. I would evaluate performance with measures appropriate to the task, use validation data to detect overfitting, and balance accuracy against interpretability, fairness, cost, privacy, and deployment constraints.

03

Professional application and growth

This artifact strengthened my ability to translate technical choices into language that managers and other stakeholders can use. In future analytics projects, I can use this framework to explain why customer segmentation, image inspection, sentiment analysis, and content generation require different tools. It also reminds me to monitor data quality and model drift after deployment rather than treating model selection as a one-time decision. Presenting the work as a portfolio artifact demonstrates both technical knowledge and communication skill, and it gives me a scalable foundation for documenting future workshops and projects.
